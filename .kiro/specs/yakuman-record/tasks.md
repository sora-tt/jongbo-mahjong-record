# 実装タスク: yakuman-record

- [ ] 1. Match契約と保存基盤

- [x] 1.1 役満種とMatch API契約を定義する
  - 一般的な役満12種と、四暗刻単騎待ち・国士無双十三面待ち・純正九蓮宝燈を別々の選択値として扱う。
  - 各イベントに和了者と役満種を持たせ、Match作成・更新入力と応答に複数イベントを通す。
  - 未対応の種別を入力境界で拒否し、runtime OpenAPIと静的SwaggerのMatch schemaへ契約を反映する。
  - Match API契約検証で作成・更新の省略可能な配列と応答のイベント配列を確認する。
  - 作成時の省略と更新時の省略・空配列の意味が契約上区別され、15種が選択肢として確認できる。
  - _Boundary: 役満種カタログ、Match記録ライフサイクル_
  - _Requirements: 1.5, 1.6, 1.7_

- [x] 1.2 (P) Match保存に役満イベントを追加する
  - Match文書へ役満イベント配列を保存・読込し、入力順を保つ。
  - 既存文書で項目が欠けている場合は空配列を返す。
  - 作成時に省略された配列を空配列として保存し、更新時の省略は既存値保持、明示的な空配列は全件削除とする。
  - Firestore schemaとEmulator検証に新フィールド、旧文書読込、更新・削除の挙動が現れる。
  - _Depends: 1.1_
  - _Boundary: Match記録ライフサイクル_
  - _Requirements: 1.3, 3.3_

- [ ] 1.3 (P) 個人別履歴の役満項目を契約へ加える
  - 個人別履歴項目に役満種配列を加え、API応答とruntime OpenAPI schemaで公開する。
  - 旧projectionに項目がない場合の空配列互換性を契約に含める。
  - 既存の認可、対象範囲、対象者、cursor、並び順を変更しない。
  - 履歴schema検証で複数種を含む応答と空配列の応答を扱える。

- [ ] 2. Match処理と画面機能
